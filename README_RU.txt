PC PERFORMANCE MONITOR — C++ x64 v1.3.5
=======================================

Платформа: Windows 10/11 x64. Сборка x86 намеренно запрещена.
Язык: C++17, Win32 API. Python/Qt для запуска не требуются.

СБОРКА
1. Установите Visual Studio 2022 Build Tools или Visual Studio с компонентами:
   - Desktop development with C++
   - Windows 10/11 SDK
   - CMake tools for Windows
2. Откройте "x64 Native Tools Command Prompt for VS".
3. Распакуйте архив и запустите BUILD_WINDOWS.bat.
4. EXE появится в build\Release\PC_Performance_Monitor_x64.exe.

SMARTMONTOOLS
Положите smartctl.exe из официального пакета smartmontools в PATH
или рядом с программой. В этой версии smartctl вызывается через командную строку.
Для полного доступа к SMART могут потребоваться права администратора и драйвер,
поставляемый с соответствующим пакетом smartmontools.

ФУНКЦИИ
- Информация о CPU и модулях RAM через WMI; объём, производитель, part number,
  штатная и настроенная скорость памяти.
- Нативный запрос NVMe SMART/Health Log (если поддерживается драйвером Windows):
  температура, запас, Percentage Used, Data Units Written, Power Cycles,
  Power-On Hours, Unsafe Shutdowns, Media Errors.
- Подробная диагностика накопителей через smartctl (если установлен).
- Запуск SMART self-test SHORT/LONG, просмотр возможностей тестирования и отмена теста для всех устройств, обнаруженных командой smartctl --scan-open.
- Информация о физических дисках.
- WHEA и Windows Memory Diagnostics: выгрузка XML событий из Windows Event Log.
- Список процессов с PID и рабочим набором памяти.
- Просмотр Run/RunOnce автозагрузки HKCU/HKLM (без изменения реестра).
- Эвристический индекс текущей нагрузки RAM: 99/75/50/25.
- История NVMe Data Units Written в CSV в %LOCALAPPDATA%\PCPerformanceMonitor.
- Анализ размера временных файлов без удаления.
- Краткий тест последовательной записи 128 MiB во временный каталог.
- Сохранение текущего отчёта в TXT.

ВАЖНЫЕ ОГРАНИЧЕНИЯ И КОРРЕКТНОСТЬ
1. Нативный NVMe Health Log зависит от версии Windows, драйвера контроллера,
   прав и поддержки IOCTL_STORAGE_QUERY_PROPERTY. Если запрос недоступен,
   используйте smartctl -x.
2. ATA и SCSI расширенные SMART-поля и самотесты получаются через smartctl.
   Добавлено прямое чтение ATA SMART через SMART_RCV_DRIVE_DATA. Поддержка зависит
   от SATA/AHCI/RAID/storage-драйвера и прав доступа; при отказе используйте smartctl.
3. TBW: программа сохраняет реальные NVMe Data Units Written, но не угадывает
   паспортный ресурс SSD. Для прогноза нужны точная модель и TBW/DWPD производителя.
   CSV позволяет сравнить накопленные снимки и вычислить средний темп записи. В текущем отчёте 128-битные NVMe-счётчики отображаются по младшим 64 битам.
4. WHEA выгружается как XML, а не сводится к диагнозу. Само наличие события
   не доказывает неисправность конкретного компонента.
5. Температура ACPI часто отсутствует или не соответствует температуре CPU/GPU.
6. Стандартного счётчика количества включений RAM-модулей обычно не существует.
7. Индекс RAM 99/75/50/25 — оценка нагрузки по занятой памяти, не процент здоровья.
8. Бенчмарк 128 MiB краткий, зависит от системного кэша и не заменяет полноценный
   тест скорости. Не запускайте его во время критичных операций с диском.
9. Автозагрузка только просматривается. Программа не удаляет записи реестра.
10. Анализ временных файлов только считает объём; автоматическое удаление отключено.
11. Не все self-test команды поддерживаются USB-мостами, RAID-контроллерами,
    виртуальными дисками и некоторыми NVMe/SCSI устройствами. Проверяйте вывод smartctl.
12. Программа не заменяет резервное копирование и профессиональную диагностику.

ПРОВЕРКА
Архив и структура исходников проверены. Компиляция и аппаратные тесты требуют
Windows 10/11 x64, MSVC и реального оборудования; в текущей среде они не выполнялись.

Дополнение: добавлен запрос ATA SMART через SMART_RCV_DRIVE_DATA. Поддержка зависит от SATA/AHCI/RAID-драйвера; при отказе используйте smartctl. Raw-значения атрибутов зависят от производителя.

Компиляция MSVC и испытания на физическом ПК в этой среде не выполнялись.

TBW: создаётся файл ssd_tbw_profiles.csv в %LOCALAPPDATA%\PCPerformanceMonitor. Формат: disk_number,rated_tbw_TB. Для расчёта среднего темпа и условного прогноза необходимы минимум два NVMe-снимка и паспортный TBW модели.


ПРОВЕРКА v1.3.1
Выполнен статический аудит исходников, проверены зависимости заголовков и библиотек, размер ATA SMART структуры и целостность ZIP. СБОРКА И ПРОВЕРКА MSVC (добавлено в v1.3.2)
-------------------------------------------
Добавлен workflow .github/workflows/windows-x64.yml для GitHub Actions.
Он запускается вручную (Actions -> Windows x64 build -> Run workflow) или
при изменении исходников. Runner windows-2022 выполняет CMake configure
с -A x64, собирает Release и загружает EXE как artifact.
Это позволяет получить фактический результат компиляции MSVC на Windows,
не считая статическую проверку ZIP подтверждением компиляции.

Локальная сборка:
- Установите Visual Studio 2022 с Desktop development with C++ и Windows SDK.
- Откройте x64 Native Tools Command Prompt for VS 2022.
- Запустите BUILD_WINDOWS.bat.
- Если сборка завершается ошибкой, сохраните полный вывод CMake/MSVC.

ОГРАНИЧЕНИЕ ТЕКУЩЕЙ ПРОВЕРКИ
----------------------------
В текущей среде нет Windows SDK и MSVC cl.exe. Поэтому добавлена воспроизводимая
Windows CI-сборка, но сам workflow должен быть запущен в репозитории GitHub.
До получения успешного лога CI программа не считается прошедшей компиляцию.


ИЗМЕНЕНИЯ v1.3.5
----------------
- Исправлена сборка строки полного smartctl-отчёта.
- smartctl --scan-open используется для обнаружения устройств; отчёт -x и
  SMART self-test SHORT/LONG/отмена выполняются для каждого найденного устройства.
- Уточнена проверка размера NVMe Health Log: проверяются смещение относительно
  структуры протокола и минимум 176 байт данных для чтения Media Errors.
- Освобождается BSTR языка WQL в WMI-запросе.
- Имя выходного EXE унифицировано: PC_Performance_Monitor_x64.exe.

Проверка v1.3.5: ZIP и статические проверки исходников выполняются при упаковке.
Компиляция MSVC и испытания на Windows 10/11 x64 не подтверждены до запуска
Windows CI workflow или локальной сборки на Windows.


Версия 1.3.4: закрытие окна теперь откладывается до завершения фоновой операции; добавлена обработка исключений фоновой задачи. Это предотвращает уничтожение HWND во время выполнения рабочего потока.


ИЗМЕНЕНИЯ v1.3.5
